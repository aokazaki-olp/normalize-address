# NJA 3.1.3 の文字の規則

`@geolonia/normalize-japanese-addresses@3.1.3` が入力文字列の文字をどう扱うかをまとめる。

- 根拠: タグ `v3.1.3`（`42cf395`、2024-12-24）のソース。行番号はこのタグでのもの
- 実測: Node v24.21.0、依存の解決結果は `@geolonia/japanese-numeral@1.1.0`、`@geolonia/japanese-addresses-v2@0.0.5`
- master（`4e694d6`）との差: `src/config.ts` と `src/lib/cacheRegexes.ts` のみ。取得の再試行と、町丁目パターンの照合順の変更（`cb575b7`）で、**文字の規則は変わっていない**

「実測」とある項目は手元で動かして確かめた。「ソースのみ」とある項目は、コードは読んだが動かしていない。

---

## 全体像：4つの層

NJA には「入力を正規の表記に書き換える規則の一覧」は無い。文字の扱いは次の4つの層に分かれる。

| 層                       | 何をするか                                                                 | 結果に出るか                   |
| ------------------------ | -------------------------------------------------------------------------- | ------------------------------ |
| 1. 前処理 `prenormalize` | 入力**全体**を書き換える                                                   | `other` に残る                 |
| 2. 照合                  | マスターの地名から正規表現を作り、表記ゆれを同じとみなす                   | 出ない（入力側は書き換えない） |
| 3. 出力                  | `pref` / `city` / `town` / `addr` は**マスターデータの表記**をそのまま返す | 入力の字形は残らない           |
| 4. 後処理                | 町字が確定した後、`other` に番地向けの置換をかける                         | `other` に残る                 |

したがって、**住所部分（`pref`〜`addr`）の字形は入力と無関係にマスターで決まる**。入力の文字が結果に影響するのは、照合が通るかどうかと、`other` の中身だけである。

## 層1. 前処理 `prenormalize`（`src/lib/normalizeHelpers.ts:10-36`）

**入力文字列の全体**に、次の順で適用する。建物名も対象に含まれる。

| #   | 規則                                                                                                 | 範囲                                                | 確認                                     |
| --- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------- | ---------------------------------------- |
| P1  | `String.prototype.normalize('NFC')`                                                                  | 全体                                                | 実測（NFD の `ヒ`+`U+3099` → `ビ`）      |
| P2  | `U+3000`（全角スペース）→ `U+0020`                                                                   | 全体                                                | 実測                                     |
| P3  | `U+0020` の連続を1つにまとめる                                                                       | 全体                                                | 実測                                     |
| P4  | `[０-９Ａ-Ｚａ-ｚ]` → 半角（`charCode - 0xFEE0`）                                                    | 全体                                                | 実測                                     |
| P5  | 横棒の統一（下記）                                                                                   | 全体（全箇所）                                      | 実測                                     |
| P6a | 最後に現れる `丁目?` `番町` `番地` `番丁` `条` `軒` `線` `の町` `ノ町` `地割` までの空白をすべて削除 | 先頭から、最初の一致1回（貪欲なので最後の出現まで） | 実測（`一条 ハイツ` の前の空白が消える） |
| P6b | 最後に現れる `郡…町/村` または `市…区`（`巿` を含む）までの空白を削除                                | 同上                                                | ソースのみ                               |
| P6c | 最初に現れる「数字 + `-`」までの空白を削除                                                           | 最初の一致1回                                       | ソースのみ                               |

### P5 横棒の統一

次の18文字を「横棒」として扱う（`normalizeHelpers.ts`・`normalize.ts`・`cacheRegexes.ts` のすべてで同じ文字クラス）。

```
- － ﹣ − ‐ ⁃ ‑ ‒ – — ﹘ ― ⎯ ⏤ ー ｰ ─ ━
U+002D U+FF0D U+FE63 U+2212 U+2010 U+2043 U+2011 U+2012 U+2013 U+2014 U+FE58 U+2015 U+23AF U+23E4 U+30FC U+FF70 U+2500 U+2501
```

長音 `ー` `ｰ` と罫線 `─` `━` を含む。

横棒のうち、次の位置にあるものを `-`（U+002D）に置き換える。

- **直前**が `[0-9０-９一二三四五六七八九〇十百千]`
- **直後**が `[0-9０-９一二三四五六七八九〇十]`（`百` `千` を含まない。左右で非対称）

数字と隣り合っていない横棒は変えない（`スーパー` の `ー` はそのまま、`スーパー10` の2つ目の `ー` だけが `-` になる）。

### 前処理がしないこと（実測）

| 入力                                  | 結果                                 |
| ------------------------------------- | ------------------------------------ |
| 半角カナ `ﾊｲﾂ`                        | そのまま（NFKC ではなく NFC のため） |
| 丸数字 `①`・ローマ数字 `Ⅱ`            | そのまま                             |
| 全角記号 `＃` `＆` `．` `（` `）`     | そのまま                             |
| 数字と隣り合わない全角ハイフン `A－B` | そのまま                             |
| タブ・改行・NBSP（`U+00A0`）          | そのまま（空白としてまとめない）     |
| 英字の大文字・小文字                  | 変えない（`ｂｌｄＡ` → `bldA`）      |

## 層2. 照合（表記ゆれを同じとみなす）

照合用の正規表現は**マスター側の地名から作る**。入力は書き換えない。

### 都道府県（`src/lib/cacheRegexes.ts:78-91`）

- パターンは `^{末尾の都道府県を除いた名前}(都|道|府|県)?`。`東京` のように末尾が無くても一致する
- **層2の表記ゆれ規則（`toRegexPattern`）は使わない**。旧字体などは都道府県名では吸収しない
- 市名が他の都道府県名で始まる場合（`千葉市` など）は、先に都道府県名を補ってから照合する（`:420-449`、`normalize.ts:205-211`）

### 市区町村（`src/lib/cacheRegexes.ts:93-116`）

- `toRegexPattern(郡 + 市 + 区)` を使う
- `町` `村` で終わる名前は `郡` の部分を省略可にする
- 都道府県が省略されたときは全都道府県の市区町村と照合し、複数が一致したら町字まで照合して決める（`normalize.ts:223-266`）

### 町字（`src/lib/cacheRegexes.ts:290-418`、`normalize.ts:99-126`）

- 入力の先頭の `大字` は取り除いてから照合する（`normalize.ts:105`）
- マスターの町字名に対して次の順に置き換えてから `toRegexPattern` を通す
  1. 横棒（上の18文字）→ 横棒のどれとでも一致する文字クラス
  2. `大字` / `字` → 省略可
  3. `(壱|一〜十の並び|全角数字の並び)` + `丁目?|番町|番丁|条|軒|線|の町|ノ町|地割|号` → `(漢数字|算用数字)` + `(丁|町)目?|番町|番丁|条|軒|線|の町?|地割|号|横棒`
     - 例: マスター `一丁目` は入力 `一丁目` `1丁目` `1-` `1町目` などと一致する
     - `壱` で始まる場合は `一` `1` `１` も認める
- `○○町` の `町` を省略した別名を登録する。ただし同じ自治体に `○○` や `大字○○` がある場合、`十六町` のように漢数字＋町の場合、京都市の場合は登録しない
- 丁目の `丁目` を省略して数字だけ書いたもの（`道玄坂1`）も最後に候補として加える（`:400-414`）
- **京都市**だけは町字を文字列の途中からも探す（`.*` を前に付ける）。このため手前の通り名が読み飛ばされる

## 層3. 出力（`normalize.ts:355-413`、`@geolonia/japanese-addresses-v2` の `data.mjs`）

| 項目             | 中身                                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------------------------- |
| `pref`           | マスターの `pref`                                                                                               |
| `city`           | マスターの `county + city + ward`                                                                               |
| `town`           | マスターの `oaza_cho + chome + koaza`。丁目はマスターどおり漢数字（`道玄坂一丁目`）                             |
| `addr`           | マスターの住居表示 `blk_num-rsdt_num-rsdt_num2` または地番 `prc_num1-prc_num2-prc_num3`（`-` 区切り、半角数字） |
| `other`          | 層1と層4を通った入力の残り                                                                                      |
| `metadata.input` | **入力そのもの**（前処理前）                                                                                    |

`addr` を求めるのは、後処理後の `other` の先頭が `^[1-9][0-9]*(-[1-9][0-9]*){0,2}` に一致し、それがマスターの住居表示・地番と**完全に一致**したときだけ（`normalize.ts:140-175`）。一致しなければ level 3 のままで、番地は `other` に残る。

## 層4. 後処理（`normalize.ts:293-340`）

**町字が確定したときだけ**、`other` の**全体**に次の順で適用する。`N` は `[0-9]+` または `[〇一二三四五六七八九十百千]+`。

| #   | 規則                                                               | 範囲   | 例（確認）                                                    |
| --- | ------------------------------------------------------------------ | ------ | ------------------------------------------------------------- |
| A1  | 先頭の `-` を除く                                                  | 1回    |                                                               |
| A2  | `[0-9]+丁目` の数字 → 漢数字                                       | 全箇所 |                                                               |
| A3  | `N番地?N号` の後ろの空白を1つにまとめる                            | 1回    |                                                               |
| A4  | `N 番地? N 号?` → `N-N`                                            | 1回    | `1番22号` → `1-22`（実測）                                    |
| A5  | `N番` + (`地` または末尾) → `N`                                    | 1回    | `アパート 百番` → `アパート 100`（実測）                      |
| A6  | `Nの` → `N-`                                                       | 全箇所 | `3の森` → `3-森`、`二の丸` → `2-丸`（実測）                   |
| A7  | `N` + 横棒 → 漢数字を算用数字に、横棒を `-` に                     | 全箇所 |                                                               |
| A8  | 横棒 + `N` → 同上                                                  | 全箇所 |                                                               |
| A9  | `N-` → 算用数字                                                    | 1回    |                                                               |
| A10 | `-N` → 算用数字                                                    | 1回    |                                                               |
| A11 | `-` + 数字以外1文字 + `N` → 全角英数を半角にし、漢数字を算用数字に | 1回    |                                                               |
| A12 | 末尾の `N` → 算用数字                                              | 1回    | `コーポ一二三` → `コーポ123`、`ビル 十一` → `ビル 11`（実測） |
| A13 | 前後の空白を除く（`String.prototype.trim`）                        |        |                                                               |

A12 は末尾の漢数字にだけかかる。`第一〇ビル` のように途中にある漢数字は変わらない（実測）。

最後に、特定の3地点（香川県まんのう町勝浦、愛知県あま市西今宿、香川県丸亀市原田町）の地番表記を補正する（`src/lib/patchAddr.ts`）。

### 漢数字 → 算用数字（`kan2num`、`@geolonia/japanese-numeral@1.1.0`）

- NJA の正規表現が対象にするのは `〇一二三四五六七八九十百千` だけ。`壱` `弐` `参` などの大字（だいじ）は変換の対象に拾われない（`一丁目弐番参号` は level 3 で `弐番参号` が残る。実測）
- `〇` を含むか、`〇〜九` だけの並びは1桁ずつ読む: `一〇` → `10`、`一二三` → `123`
- それ以外は位取りで読む: `十一` → `11`、`百` → `100`

## ラッパー設計への含意

- 住所部分の字形はマスターが決めるので、ラッパーが合わせる対象になるのは建物部だけである
- 層1のうち **P1〜P4 は字形の規則**（NFC、全角スペース、空白の連続、全角英数）。層1の P5・P6 と層4は**番地の構造を読むための規則**で、建物名にかけると壊れる
- 3.1.3 はデータ取得の応答が正常かを確かめない（master で修正済み・未リリース）。CDN が一時的なエラーを返すと、例外にならず低い level に黙って落ちる
- `japanese-numeral` は `^1.0.2` 指定で、今回は 1.1.0 に解決された。lockfile で固定しないと挙動が変わりうる
